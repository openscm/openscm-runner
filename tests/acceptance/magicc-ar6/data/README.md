# Acceptance test data for the MAGICC AR6 adapters

MAGICC v7.5.3 with the AR6 probabilistic distribution
(`0fd0f62-derived-metrics-id-f023edb-drawnset.json`).

## MAGICC AR6 is an exception

Normally, the adapter writer (model team) provides the acceptance data
and we don't generate it ourselves (see `docs/testing.md`).
MAGICC AR6 is an exception: we generate the data here.
It is here to demonstrate how acceptance data like this could be generated.

## How the data is generated

The acceptance data in each directory is generated by the script in that directory
(`generate_data.py`),
within the environment specified by the script's
[PEP 723](https://peps.python.org/pep-0723/) inline metadata
(which includes the Python version)
and its lock file (`generate_data.py.lock`, made with `uv lock --script`).
To regenerate the data, run (from the directory):

```sh
uv run --script generate_data.py
```

The exception: the AR6 scenario adapter and its variants
(`ar6-scenario`, `ar6-scenario-anthropogenic-only`
and `ar6-scenario-co2-forcing-only`) are all generated by
`ar6-scenario/generate_data.py`.
We generate them all in one script so the data generation can't get out of sync
between them and it is obvious what the difference between the cases is
(see `CASES` in the script),
rather than people having to diff multi-hundred line files.

We do it this way because producing the data needs other packages
(e.g. pymagicc, which only works with old versions of pandas, xarray etc.)
and we don't want to create a dependency conflict nightmare for ourselves:
these scripts only need to be run once (and are only tracked for provenance).

Rules for the scripts:

- they never import `openscm_runner`:
  the point is that they are an independent route to the same answer
- they get MAGICC v7.5.3 and the AR6 probabilistic distribution as the tests do
  (see `.env.sample`): from the paths in `MAGICC_AR6_V753_ROOT_DIR`
  and `MAGICC_AR6_PROBABILISTIC_DISTRIBUTION` or, if they aren't set,
  downloaded from magicc.org (pinned hashes) with the token in `MAGICC_AR6_DOWNLOAD_TOKEN`
  (run them with `uv run --env-file <repository root>/.env --script ...`)
- "the first ensemble member" is the first entry
  in the distribution's `configurations` list.
  The expected outputs identify it by its `paraset_id`
  (in the `ensemble_member` column)
  and the tests check that the adapter gives it the same ID
- any URLs are pinned to a commit SHA

Inputs shared between adapters (e.g. the infilled AR6 emissions)
go in `tests/test-data`, with their own generation script and lock file.

## What is committed

The generated data (inputs and expected outputs) is committed.
MAGICC v7.5.3 and the AR6 probabilistic distribution are licensed,
so they are never committed.
The tests use your copies (if you set the paths)
or download the official versions from magicc.org with a token (see `.env.sample`).
Without either, the acceptance tests fail (they don't skip).

## Layout

One directory per adapter (named after the adapter in kebab case,
without the `MAGICCAR6Adapter` prefix), each with
`generate_data.py`, `generate_data.py.lock`, `input.csv` and `expected-output.csv`
(see "File format" below, exceptions noted below):

- `erf-driven-from-equilibrium`: `MAGICCAR6AdapterERFDrivenFromEquilibrium`,
  first ensemble member, two inputs
  (a ramp with an eruption-like dip and an abrupt step)
- `ar6-scenario`: `MAGICCAR6AdapterAR6Scenario`, first ensemble member,
  one AR6 scenario (AIM/CGE 2.2 EN_NPi2020_900f).
  The input is shared with other tests,
  so it is in `tests/test-data/ar6-scenarios` (with its own script),
  not in this directory.
  The full-ensemble test compares with AR6's published temperature percentiles
  (also in `tests/test-data/ar6-scenarios`), so it has no data here.
- `ar6-scenario-anthropogenic-only`: `MAGICCAR6AdapterAR6ScenarioAnthropogenicOnly`,
  as for `ar6-scenario` (same input), with only anthropogenic forcing
  driving the climate (`RF_TOTAL_RUNMODUS = "ANTHROPOGENIC"`).
  Only `expected-output.csv`: it is generated by `ar6-scenario/generate_data.py`
  (see "How the data is generated" above)
- `ar6-scenario-co2-forcing-only`: `MAGICCAR6AdapterAR6ScenarioCO2ForcingOnly`,
  the CO2 emissions from the same input as `ar6-scenario`,
  with only CO2 forcing driving the climate (`RF_TOTAL_RUNMODUS = "CO2"`)
  and everything except CO2 held at pre-industrial (1750).
  Only `expected-output.csv` (generated by `ar6-scenario/generate_data.py`,
  see that directory's README for the details).
  This may still change because what is meant by CO2-only is still unclear
  (e.g. which feedbacks should be included, see roadmap item B16)

## File format

Wide CSV: one row per timeseries, one column per year.
Every column that isn't a year is an index level
(at least `scenario`, `variable`, `region`, `unit`).
Each value in the `scenario` column is one experiment.

`input.csv` must pass the matching `verify_*` function
(e.g. `verify_erf`).
`expected-output.csv` contains the outputs the adapter should produce
from those inputs: the variables in it are the outputs the test requests.
It also has an `ensemble_member` column with the ID of each ensemble member
(the AR6 probabilistic distribution's `paraset_id`).
It only has some years (2015, then every ten years from 2020 to 2100):
checking every year doesn't add much and this saves a lot of space.
Where the response changes quickly, we keep every year
(e.g. for 10 years after the abrupt step and the eruption-like dip
in `erf-driven-from-equilibrium`).

Values are rounded to six significant figures,
so re-running the script doesn't produce diffs from floating-point noise
and git can track changes sensibly.
The comparison tolerances (in the test file) are looser than this rounding.

Why CSV rather than JSON:
wide CSV is one line per timeseries,
so a diff shows exactly which timeseries changed.

## Adapters without acceptance tests

The CMIP adapters (`MAGICCAR6Adapter*From{CMIP6,CMIP7}PreIndustrial`)
don't have acceptance tests.
Making MAGICC v7.5.3 branch from piControl takes a lot of setup
(see `src/openscm_runner/adapters/magicc_ar6/cmip_pre_industrial_branch.py`)
and reproducing that independently is more trouble than it's worth,
so they are checked by the integration tests only
(`tests/integration/magicc-ar6/`).
They will be removed before merging to main,
because they don't meet the definition of done
(we may put them in private repos if we need to use them for other work).
